# EuroBaza Project — Полные правила работы для ИИ

## 1. Ничего наугад
- Перед любым изменением опираться только на реальный код файлов, реальные ключи Firebase (`users`, `labels`, `accounts`, `online`, `chat`, `dm`, `config`) и реальную разметку HTML/CSS. Не придумывать несуществующие функции, переменные и селекторы.

## 2. Формат работы в Termux
- Пользователь работает в Termux на Android. 
- Локальный агент Antigravity читает, редактирует файлы и запускает команды напрямую через свои инструменты (команды ручной вставки `cat << 'EOF'` не требуются).

## 3. Обязательная проверка целостности (`node check.js`)
- Любая правка кода должна обязательно завершаться запуском `node check.js`.
- Ни один коммит не отправляется на GitHub и ни один ответ не выдаётся пользователю, пока `node check.js` не подтвердит отсутствие синтаксических ошибок во всех `.js`, `.json`, `<script>` в `.html` и валидность `style.css`.

## 4. Синхронизация версии и кэша PWA (Строго 4 файла)
- После любого изменения кода обновлять 14-значную версию (`YYYYMMDDHHMMSS`) строго сразу в 4 файлах:
  1. `version.json`
  2. `sw.js` (`CACHE_NAME = 'eurobaza-v...'`)
  3. `index.html`
  4. `admin.html`
- Запрещено менять код без обновления Service Worker кэша, иначе клиенты получают устаревший кэш из браузера. Затем отправлять изменения на GitHub (`git add -A && git commit -m "..." && git push origin main`).

## 5. Единый стиль интерфейса и модальных окон
- Не использовать системные `alert()`, `confirm()` и `prompt()`. 
- В основном приложении использовать `askC()` и `toast()`, в админ-панели — `ask()`, `askInput()` и `toast()`.

## 6. Совместимость и локализация (3 языка)
- Учитывать 3 языка интерфейса (`ru`, `hy`, `en` в `i18n.js` и `auto-translations.json`), мобильную вёрстку, безопасные отступы iOS/Android и работу Service Worker в офлайн-режиме.

## 7. Защита файлов контекста и скелета
- При обновлении `EuroBaza для ИИ/EuroBaza_CONTEXT.md` обновлять только секцию с версией и кодом файлов, обязательно сохраняя раздел с правилами.

## 8. Команда «Обнови для ИИ»
- Обновление `EuroBaza_CONTEXT.md` и `EuroBaza_SKELETON.md` выполняется командой:
  `cd "/sdcard/Download/EuroBaza Project" && node update-context.js`
  (скрипт сам сохраняет раздел с правилами и заметками, обновляя версию и код).

## 9. Сбор контекста для задачи в единый `.md` файл
- Если внешнему ИИ не хватает кода или данных, генерируется единый файл `/sdcard/Download/EuroBaza Project/EuroBaza для ИИ/EuroBaza_TASK.md`, чтобы пользователь скинул этот файл в чат без накопления лишних файлов в Download.

## 10. Краткость ответов
- Писать как можно меньше текста, но чтобы пользователю всё было понятно. Всегда отвечать строго на русском языке.

## 11. Каталоги моделей мебели
- Справочники и каталоги моделей находятся в папке `EuroBaza Каталоги/` в корне проекта (`eurobaza_models.json`, `eurobaza_doors.json`, `eurobaza_all_items.json` и др.).

## 12. Правила базы данных Firebase
- Файл с актуальными правилами безопасности хранится в `EuroBaza для ИИ/Правила FireBase.md`.
- При добавлении или изменении любых функций, затрагивающих Firebase, ИИ обязан проверить соответствие правилам: если логика требует новых узлов или прав доступа, ИИ должен обновить `EuroBaza для ИИ/Правила FireBase.md` и предупредить пользователя об обновлении в консоли Firebase.
- Не стирать метки прочитанных сообщений при выходе из профиля (`pmOut`).

## 13. Разделение ролей Главного админа и Субадмина (Отдел доставки)
- В админ-панели субадмин (`diannakirakosyan@gmail.com` — Отдел доставки) имеет доступ только к своей переписке (`dlv`), OCR и просмотру.
- Главный админ (`vazgenstepanyan2002@gmail.com`) имеет полные права управления.
- Локальные состояния и метки прочитанного (`ADM_DM_SEEN_ADM` и `SUBADM_DM_SEEN_DLV`) субадмина и админа должны быть строго изолированы друг от друга, чтобы действия одного не затирали уведомления другого.
